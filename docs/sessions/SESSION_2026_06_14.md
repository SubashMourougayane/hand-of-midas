## Decisions Made

1. **No auto-ship rule (LOCKED IN).** Every filter, every type, gets the full 19-step workflow including BT pre/post measurement and explicit user ship/stash decision. No exemption for "obviously correct" or "$0 BT impact" or "bug fix grade." User pushback on Filter #15 made this rule explicit. See `feedback_no_auto_ship.md`.

2. **Selective ship via per-system config keys (LOCKED IN, applied to #5/#6/#7).** When a filter helps some systems and hurts others, ship to the helping subset only. `cfg.get("key", default)` pattern provides safe fallback for excluded systems.

3. **Code-level filter measurement via `git checkout` runner.** For filters that aren't kwarg-gateable (e.g. #15 race fix is a code refactor, not a parameter), `scripts/run_filter_15.py` is the template: checkout pre-fix commit → BT → checkout post-fix → BT → compare. Two separate Python invocations to avoid module-cache contamination.

4. **Strategy edge is fill-side, not signal-side (DATA-CONFIRMED).** 6 independent signal-pruning mechanisms all lose P&L. 4 fill-side filters all shipped (#5/#6/#7 + #11). Future R&D should focus on fill-side variants.

5. **Telegram via sync httpx for one-shot scripts.** `notify.send()` daemon thread is broken for end-of-script use.
