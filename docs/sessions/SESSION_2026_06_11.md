## What Happened (Chronological)

### Phase A — Two BCO trades, both losing
User reported two trades closed: `OIL-MI-c1f44df4` (-$430.56) and an unrelated trade with broker_id `2034232555` (-$577.08). The second wasn't in DB at all — investigated as a new orphan, then discovered it had been placed by a **local Mac instance of `backend-oil-micro/main.py` running for 2+ days on port 5056**, racing with the VPS for orders on the shared JustMarkets demo account.

### Phase B — Killed local duplicate scanner
PID 74577 killed. All 4 trading ports verified free. Same-account-two-services failure mode that CLAUDE.md explicitly warns against, hit on the new platform.

### Phase C — Fix Y: ON CONFLICT partial-index match
`ORPHAN_ADOPT_FAILED` cascade was a real SQL bug (140 events for ticket 2034232555). The reconciler's `INSERT … ON CONFLICT (oanda_trade_id) DO NOTHING` couldn't match the partial unique index because Postgres needs the predicate explicitly. Added `WHERE oanda_trade_id IS NOT NULL` to all 4 reconcilers. Verified via `scripts/verify_orphan_reconciler_fix.py` and `test_orphan_conflict_syntax.sql`.

### Phase D — Fix Z: Cross-system + RETURNING id dedup
After Fix Y deployed, real-world test produced **22 ORPHAN_ADOPTED Telegrams in 22 minutes** for the same legitimate Oil Macro trade (`OIL-AS-5434644d`). Root cause: each system's reconciler pre-check filtered by its OWN trade_ref prefix (`OIL-MI-%`), so Oil Micro saw Oil Macro's position as an "orphan" and re-attempted the INSERT every cycle. ON CONFLICT silently does nothing without indicating skip, so notify+journal ran every cycle. Fix: drop trade_ref prefix filter (each system now sees ALL DB-tracked broker_ids), add `RETURNING id` to detect actual insert vs. silent skip.

### Phase E — Macro phantom-fill fix
While debugging the orphan spam, user noticed Telegram said `OIL-AS-5434644d closed at SL -$1054` while JustMarkets web showed it was still OPEN (unrealized -$572). **Same bug class as June 10's `GD-MI-cce2a254` phantom fill, but in Oil Macro instead of Micro.** Macro engines never got the broker-authoritative close-detection; they were still using a proximity heuristic. Wrote `scripts/revive_OIL-AS-5434644d.py` to roll back the false close, then ported the Micro pattern (`get_trade_details` reading `closed_orders.json` from DWX EA's `OnTradeTransaction`) to both Gold Macro and Oil Macro. Plus latent Gold Macro bug fixed: was reading `details["price"]` (the open_price in closed_orders.json shape) instead of `close_price`.

### Phase F — L99 adversarial review found 5 more bugs
Spawned an investigator agent to comb tonight's commits for regressions. Found:
- **C1 (CRITICAL):** Gold Macro's `check_open_positions` query had no system filter — would process ALL systems' open trades under Gold's DD row and fire wrong-instrument Telegrams on cross-system races.
- **C2 (HIGH, latent):** OANDA wrapper's `get_trade_details` didn't return `close_price`/`exit_reason` — accidental EXECUTOR=oanda flip would silently corrupt every Macro exit.
- **P1 (MEDIUM):** Stuck `EXIT_AMBIGUOUS` had no alarm; could go unnoticed indefinitely if DWX EA broken.
- **P3 (LOW):** New `EXIT_AMBIGUOUS` calls used `_log_journal` not `_log_journal_safe`, inconsistent with surrounding hardening.
- **P4 (MEDIUM):** Oil Macro `execute_signal` INSERT not in try/except, race window with reconciler.

All 5 fixed in commit `fba8fdd`. `EXIT_AMBIGUOUS` 5-cycle Telegram alarm added.

### Phase G — C1 part 2: UI route filters
Discovered after restart: Gold Macro `/live` page showed Oil Macro's open BCO position. Three more unfiltered queries in `backend/routes/state.py`, `backend/routes/stream.py`, `backend/routes/journal.py`. All filtered by `strategy IN (...)`.

### Phase H — Harness isolation by comment prefix
User confirmed many small XAUUSD 0.01-lot trades in JM history were from `tests/harness/test_10_live_runtime.py` running against the shared demo account. Reconciler had adopted one of them (`GD-MI-orphan-36627933`) with `units=0` (because `int(-0.01) = 0`). Two-part fix:
- Reconciler skips if `comment.lower().startswith('harness')` (existing harness tests already use this pattern).
- Reconciler rejects `units < 1` after `round()` regardless of source.
- DWX MT5 wrapper now exposes `comment` field; OANDA wrapper mirrored for parity.
- Cleanup script `scripts/cleanup_GD-MI-orphan-36627933.py` marked the existing ghost row as ORPHAN_CLEANUP.

### Phase I — DWX OnTradeTransaction handler gap (the night's discovery)
After all the fixes deployed, real Oil Macro SL fired at broker level (~22:23 server). The new EXIT_AMBIGUOUS safety net **correctly refused to phantom-fill**, logged 6 streak events, fired Telegram alarm at streak 5, but `closed_orders.json` was never written for this trade. **Same EA worked correctly for `GD-MI-cce2a254` (10:04 UTC) and `OIL-MI-c1f44df4` (13:26 UTC) earlier today.** Investigation showed local Mac DWX dir has NO `closed_orders.json` file at all (never created), suggesting the Mac EA is running an older compiled version. When MT5 dispatched this particular deal event to the Mac instance, no record was written. Postmortem at `docs/trades/OIL-AS-5434644d.md`. Manual close script `scripts/close_OIL-AS-5434644d.py`.

- **Killing local duplicate scanner > investigating its bug.** PID 74577 had been writing to a different DWX dir than the VPS, so its order placements bypassed VPS journaling. Could have debugged why it wasn't getting cleaned up after deploys, but killing it eliminates the entire class of dual-source-of-orders bugs.

- **Did NOT push fixes blindly.** L99 review caught 5 bugs in tonight's earlier fixes. Adversarial review is now part of the workflow before declaring "done."
