### Bugs Found & Fixed

#### BUG: max_trades_per_day bypassed (Jun 3 — 5 trades in one day)

**Root Cause:** DB INSERT for earlier trades failed silently. Next cycle queries DB `SELECT COUNT(*)` → sees 0 → allows unlimited re-entry. Cascading failure: one failed INSERT disables ALL guards for rest of day.

**Fix (commit b6bfced):**
1. `trades_today = max(db_count, _daily_state["trades"])` — local counter survives DB failures
2. One-at-a-time also checks `get_open_trades()` on MT5 directly — catches orphans

#### BUG: P&L = $0 on MAX_HOLD exits

**Root Cause:** DWX EA `close_trade` response doesn't include `profit` field. Code used `result["realized_pl"]` which defaulted to 0.

**Fix (commit a87ba06):** Calculate P&L from entry/exit/units/direction:
```python
if trade["side"] == "SHORT":
    realized_pl = (entry_price - close_price) * trade_units
```
Applied to: Macro, Micro, Oil live_engines.

#### BUG: Macro API returning Micro trades

**Root Cause:** No `trade_ref` filter in Macro trades query.

**Fix:** Added `AND trade_ref LIKE 'GD-AL-%%'` to Macro trades route.

#### BUG: Oil trades never detected as closed

**Root Cause:** `get_trade_details()` returns None on MT5 (never returns "CLOSED"). Old code logged "DETAILS_FETCH_FAILED" and continued — trade stuck open in DB forever.

**Fix:** When trade gone from MT5, determine SL/TP from current price proximity, calculate P&L, record exit.

#### BUG: Trade 5 (Jun 1) placed without SL

**Root Cause:** Either sl_price was 0/None or broker accepted order without SL silently.

**Fix (commit 84532a0):** Reject signal if `sl_price <= 0` before placing order.

#### BUG: TP already passed when order placed (Jun 2 "Invalid stops")

**Root Cause:** Small range ($10.5), TP calculated at $4,480, but by order time price was $4,482 (past TP). Broker rejected.

**Fix (commit 471b41b):** Validate TP is on profitable side of current price before ordering.

### Key Discovery: Backtest Engine Import Collision

When testing locally with `sys.path` containing both `backend/` and `backend-micro/`:
- `from backtest.engine import run_backtest` resolves to `backend/backtest/engine.py` (MACRO)
- NOT `backend-micro/backtest/engine.py` (MICRO)

This caused confusion where local tests showed 640 trades (wrong engine) vs VPS showing 1,592. Live trading was never affected (each service runs in its own process).

**Fix:** Use `importlib.util.spec_from_file_location()` to explicitly import the correct engine file.

## Key Learnings This Session

1. **DB INSERT failures cascade** — one failed INSERT disables all guards for the day. Always use local counters as backup.

2. **MT5 is source of truth, not DB** — one-at-a-time must check MT5 directly, not just DB.

3. **DWX EA responses are incomplete** — never trust `result["profit"]` from close command. Always calculate P&L ourselves.

4. **Combined bias is more conservative** — blocks more trades. Oil Macro can't survive it (needs rolling windows). Gold works fine.

5. **V2 bias was WORSE than V1 for downtrends** — V2 (close position 80/20) allowed LONGs during Jun 1-3 crash that V1 (body% > 40%) would have blocked. Combined catches both patterns.

6. **Oil Micro is the biggest untapped opportunity** — PF 6.98, 85.9% WR, $1.21M over 20 years. Current Oil Macro makes money but leaves most on the table.

7. **Backtest import collision** — `backend/backtest/engine.py` shadows `backend-micro/backtest/engine.py`. Always use explicit file path imports when testing locally.

8. **The losing streak was mostly bugs + trend** — Bug-caused losses: ~$1,220 (Jun 3 guard bypass). Trend-caused losses: ~$2,500 (buying into a crash). System is now fixed and adapted.
