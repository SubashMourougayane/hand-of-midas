### Phase A — Drift bug #6 (commit `80ba0d3`)
All 4 backtest engines used `bar.date()` to key into `daily_bias`, but OANDA `dailyAlignment=21` makes the bar's calendar date 1 day **before** its actual trading session. So a bullish bar in session N was being labeled with bias from session N-1, producing ~75% same-direction next-bar correlation that inflated PF artificially. Fixing it across 4 engines:
- True P&L: $7,330,549 → **$3,224,099**
- True PF: 4.29-5.58 → **2.42-2.69**
- True WR: 78-91% → **54-70%**

Real numbers are still profitable; the system just isn't a money cannon. See `docs/EDGE_FILTERS_RESULTS.md` for pre/post tables.

## Decisions Made

1. **Strict-additive logging** (existing `print()` calls preserved). Why: rewriting ~120 print calls for low gain in time-bounded session = high risk for no benefit. Both old prints and new `_log.x()` calls go to the same stdout → same log file.
2. **Text logger via `print()` wrapper, NOT Python `logging` module.** Why: start-win.bat's stdout redirect would race with a `FileHandler`. Wrapping print is mechanical, fail-safe, zero deps.
3. **Default log level DEBUG.** Why: user explicitly chose max observability for the dark-week. ~10-50MB/svc/week is acceptable.
4. **Restart-based rotation** (not date-based). Why: services rarely restart; date rotation adds complexity for no benefit.
5. **Try/except-wrap every public logger function.** Why: logging bug must never crash scheduler during a 7-day dark period.
6. **Defer Gold-Micro market_close fix.** Why: user went dark immediately. Need JM hours spec verified first; +$27k in 21-yr backtest is patient.
