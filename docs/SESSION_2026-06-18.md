## Decisions Made

### F28 ship strategy: Multi-stage opt-in via env vars (not config commit)
**Why:** Per `[[feedback-user-explicit-opt-in]]`. Default `production` on git pull = zero behavior change. User flips ONE system at a time via VPS .env. Watch 5-7 days per system before next flip.
**How to apply:** This pattern is the standard for any new strategy-affecting feature. Default OFF, per-system manual flip, observation window before next.

### Path A → Path B → Multi-seed → DD/Sharpe/MC sequence
**Why:** Each gate de-risks the next:
- Path A: discovery (does the change work in BT?)
- Path B: clean engine kwarg (validates that production-side path produces identical numbers to research-side patch)
- Multi-seed: slippage RNG check (is this single-seed luck?)
- DD/Sharpe/MC: risk gates (is the absolute P&L gain offset by hidden risk?)
**How to apply:** Use this sequence for any future filter-sweep candidate that targets a structural strategy gate (vs an observability bug fix).

### F31 parked behind F30
**Why:** F31 (DXY) has same V1+V2 risk pattern (directional pre-filter vs mean-reversion). F30 (SMC) is structurally aligned with our strategy. F30 has higher prior of working. Test F30 first; F31 only becomes interesting if F30 wins (then potentially stack).
**How to apply:** When 2 candidates target the same gate, test the structurally-aligned one first.

### Sweep-walker research: don't redesign entry definition
**Why:** Production caught 9,245 trades over 21yr at 78.7% WR. Looser variants caught more "sweeps" but at 40-50% WR. NoProd→Caught is pennies per day across 5,661 days. **Strategy entry definition is sound; live edge gap is execution layer.**
**How to apply:** Future "we're missing setups" arguments require this 21yr analysis before any change. Visual eye spots single-day misses; 21yr says they're within distribution.

### F28 audit framework reused from F27
**Why:** Same VERIFY → RCA → FIX → TEST framework, same lifecycle markers, same phase-plan structure. Catalog of 17 items in tier order. Same shape as `docs/FILTER_27_AUDIT_BACKLOG.md`.
**How to apply:** Per `[[feedback-bug-fix-framework]]`, this is the standing framework for any audit-discovered backlog. Don't reinvent.
