### Phase B — Two more bugs found while looking at June 9 trades
While analyzing why two June 9 afternoon Gold Macro trades (R:R 0.46 + R:R 38.7) lost money:
- **Gold Macro had `check_alpha_sweep_breakeven()` imported but never called** in `position_monitor_job`. Trade reached $4,325 (50% to TP) → BE should have armed → didn't → original SL hit. Cost: $408 on those 2 trades alone. Fixed in `d6f98a8`.
- **Gold Micro's scheduler had `get_open_trades()` call at line 307 but missing from line 10 import**. Every scan cycle since June 6 had been crashing silently with NameError. Production journal confirmed 100/100 recent events were that exact error. Fixed in `cd7c843`.

### Phase C — The orphan-trade cascade discovery
Throughout the day, Oil Micro placed 7 BRENT SHORT orders that the user could see on JustMarkets web but had **zero rows** in `gd_trades`, `gd_signals`, `gd_journal`. No Telegram notifications fired. User closed all 7 manually for net **+$345.86** (5W/2L).

Initial hypothesis was the numpy/Decimal serialization issue in `_log_journal`. Built defense-in-depth around that hypothesis. Then while running the reset SQL, hit `value too long for type character varying(20)` — found the actual root cause: `gd_trades.strategy` was `VARCHAR(20)`, but Oil Micro's strategy name `'micro_alpha_sweep_oil'` is **21 chars**. Every Oil Micro DB INSERT had been silently overflowing.

### Phase D — Defense in depth (7 layers)
Even though the schema fix is the actual root cause, kept the other layers because they prevent the entire CLASS of similar bugs:
1. `safe_json_dumps` for numpy/Decimal/datetime
2. `_log_journal_safe` swallows exceptions in critical paths
3. Sweep blacklist updated BEFORE `execute_signal`
4. DWX EA preserves full comment
5. `reconcile_orphans()` every 60s in all 4 systems, idempotent ON CONFLICT, fires Telegram
6. Daily recon Telegram at 00:05 UTC per system
7. Schema VARCHAR(50) for all `strategy` columns

### Phase E — Side discovery: OANDA stream still hammering broker
While investigating, noticed Oil Macro's journal was 200/200 `STREAM_DISCONNECTED` events. Turned out 3 of 4 services (Oil Macro, Gold Micro, Oil Micro) had never been updated for the OANDA→MT5 migration — they were still calling `start_stream()` unconditionally with empty `OANDA_TOKEN`, reconnecting every 3 seconds, flooding the journal. Only Gold Macro had the `EXECUTOR != "mt5"` guard. Fixed in `e71b53f`.
