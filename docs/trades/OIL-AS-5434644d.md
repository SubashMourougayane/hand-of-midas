## 2. Bug-smell scan (judgment)

<!-- skill: bug_smell -->
**This trade is the canary for the DWX OnTradeTransaction handler not firing reliably.** Three correlated facts:

1. **Earlier today, Gold Micro's `GD-MI-cce2a254` close (10:04 UTC) DID journal `EXIT_FILLED` with broker-authoritative data.** That proved `OnTradeTransaction` works for Gold Micro.
2. **Oil Micro's `OIL-MI-c1f44df4` close (13:26 UTC) DID journal `EXIT_FILLED`.** Proves it works for Oil Micro too.
3. **Oil Macro's `OIL-AS-5434644d` close (~20:23 UTC) did NOT journal anything.** No `EXIT_FILLED`, no entry in `closed_orders.json` (verified absent on Mac DWX dir; very likely absent on VPS DWX dir given DB unchanged).

Why would the same EA write closed_orders.json for Micro trades but not Macro? Possibilities, ranked:

- **(Most likely) Two MT5 instances are running on the same broker account** — Mac MT5 and VPS MT5. The OnTradeTransaction handler is **per-EA-instance**, not per-account. Whichever EA happened to be the one MT5 dispatched the trade event to writes the file. If the trade was dispatched to a stale Mac EA (without the OnTradeTransaction code), the VPS EA never sees it. **Earlier today the Micro trades happened to land on the VPS EA; this Macro trade landed on the Mac EA which doesn't have the handler.**
- **(Less likely) DEAL_REASON filter rejected this fill** — if MT5 reported the deal with a `DEAL_REASON` value that's not in `{SL, TP, SO, CLIENT, EXPERT}`, the EA's reasonStr would be UNKNOWN. But the early `if` checks on line 561, 565, 569, 574 wouldn't reject — only the reasonStr would be UNKNOWN. So the file should still have been written.
- **(Very unlikely) Race with DWX file lock** — the 5-cycle alarm gives plenty of time (5 minutes) for the file to populate. If it didn't populate in 5 minutes, it never will.

**Cross-check:** the local Mac EA was confirmed to have NEVER created a `closed_orders.json` file (no such file on disk at all). That's strong evidence the Mac EA is running an OLD compiled version that doesn't have OnTradeTransaction. When the user said "DWX EA recompiled twice today," that was on the VPS MT5 — the Mac MT5 was overlooked.

The new `EXIT_AMBIGUOUS` Telegram alarm did exactly what it was designed to do: refused to phantom-fill the DB at a guessed price, and surfaced the failure to the user within 5 minutes. **This is the system working as intended in a degraded state.** The right fix is to make Mac and VPS EAs consistent OR to stop running the Mac EA entirely.
